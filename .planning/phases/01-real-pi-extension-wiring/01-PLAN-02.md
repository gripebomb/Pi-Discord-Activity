### Task 02: Add state transition deduplication

**Objective:** Prevent duplicate presence publishes for same state

<read_first>
- `src/extension/index.ts` - extension factory (from PLAN-01)
- `src/extension/state.ts` - after Task 01
</read_first>

<action>
Update the extension factory to avoid publishing the same state multiple times:

1. Track the last published state in the factory
2. Only call publishPresence if the state actually changed

Example implementation in factory:
```typescript
let currentState: string | null = null;
let currentProvider: string | null = null;
let currentModel: string | null = null;

function shouldPublish(newState: string, newProvider?: string, newModel?: string): boolean {
  // State change always triggers publish
  if (newState !== currentState) return true;
  
  // Provider/model change also triggers publish (even if state same)
  if (newProvider && newProvider !== currentProvider) return true;
  if (newModel && newModel !== currentModel) return true;
  
  // Same state, same labels - no publish needed
  return false;
}

function updateAndPublish(state: string, provider?: string, model?: string) {
  if (shouldPublish(state, provider, model)) {
    currentState = state;
    if (provider) currentProvider = provider;
    if (model) currentModel = model;
    void publishPresence(state.setActivity(state));
  }
}
```

Update each event handler to use `updateAndPublish()` or a similar pattern.
</action>

<acceptance_criteria>
- [ ] Extension only publishes when state/label actually changes
- [ ] No duplicate presence updates for same state
- [ ] Provider/model changes trigger publish even if state unchanged
- [ ] TypeScript compiles without errors
</acceptance_criteria>
